## Limits of this evaluation

- The case rule treats unusual capitalization as a defect and writes the value in title or sentence case. 291 of the 291 loaded fields that differ from the clean data (in the first runs) differ only in capitalization, which is what happens to acronyms and names that are written with capitals in the middle on purpose. A person can remove or change the rule in the transform preview.
- The clinic defects that are not quarantined (6 of 2,057) are all out-of-range values in `patients.HEALTHCARE_EXPENSES`, a source field that the clinic target schema has no column for. It is not mapped and not loaded, so a value in it can be reported by profiling but is never checked at load.
- Two systems are a small sample. The figures show that the method works on these two, not how it will do on any legacy system.
- The defects are injected by the fixture builder, which also writes the answer. Natural oddities in the data are reported by the platform and are not counted as errors, so precision is informational.
- Timings come from one machine in one process and depend on it; the stage ratios matter more than the seconds.
- The repeat run shows the effect of the mapping memory. The effect of the model cache can only be seen when a provider is configured, and is zero here when it is not.
